# 思源易搭 siyuan-query-builder PRD

~思源笔记

## 项目名称

查询构建器 + 多视图结果面板（第一阶段）

## 一、项目背景

思源笔记已经具备较强的块级数据能力，包括块引用、属性、嵌入、查询等。但这套能力对普通用户而言门槛仍然偏高。

当前问题不在于系统没有能力，而在于：

- 高级能力主要被少数懂 SQL 或懂系统结构的用户使用
- 大多数用户无法将查询能力转化为日常工作流
- 即使查出结果，也缺少可视化、可交互的消费方式

因此，第一阶段产品目标不是继续增强底层查询本身，而是降低查询使用门槛，并把查询结果升级为可操作视图。

## 二、项目目标

### 目标

- 让普通用户无需写 SQL，也能构建常见查询
- 让查询结果能以表格、看板、日历等形式展示
- 让查询结果可复用、可保存、可嵌入
- 为后续任务中心、自动化规则、知识库仪表盘提供统一底座

### 非目标

- 不在第一阶段实现完整数据库系统
- 不在第一阶段实现复杂跨库计算引擎
- 不在第一阶段覆盖所有高级 SQL 特性
- 不在第一阶段做完整自动化规则系统

## 三、目标用户

### 核心用户

- 用思源管理知识、项目、资料的人
- 会使用块、标签、属性，但不会写 SQL 的中级用户
- 已感受到信息增多后检索和整理效率下降的用户

### 次级用户

- 重度用户，希望快速搭建任务视图、项目看板、阅读清单
- 高级用户，希望用更快方式搭建查询原型，而非每次手写 SQL

## 四、用户痛点

### 痛点 1：查询能力强，但不会用

用户知道思源可以查，但不知道怎么写条件、字段、排序、分组。

### 痛点 2：查询结果不适合日常操作

即使查出来，也更像技术输出，不像真正可用的工作界面。

### 痛点 3：重复搭建成本高

同样的查询场景需要重复写、重复改、重复保存。

### 痛点 4：数据和界面脱节

用户希望围绕块内容管理任务、项目、阅读、会议记录，但缺少统一交互入口。

## 五、核心使用场景

### 场景 1：任务清单

用户想查看所有状态为“进行中”且截止日期在本周内的任务。

### 场景 2：项目看板

用户想把所有带有项目属性的块按状态分组，形成 To Do / Doing / Done 看板。

### 场景 3：阅读清单

用户想查看所有“未读”书籍或文章，并按主题或优先级排序。

### 场景 4：会议记录回顾

用户想聚合最近 30 天的会议记录，并按项目归类。

### 场景 5：知识盘点

用户想查看最近新增但尚未打标签、尚未建立引用关系的内容。

## 六、产品方案概述

第一阶段包含两个核心模块：

- 查询构建器 Query Builder
- 多视图结果面板 Multi View

二者关系如下：

- 查询构建器负责“定义要看什么”
- 多视图结果面板负责“怎么展示和操作”

## 七、模块一：查询构建器 Query Builder

### 7.1 功能目标

让用户通过界面式配置完成常见查询搭建。

### 7.2 核心能力

- 选择查询对象范围，例如笔记本、文档、块类型、标签、属性
- 配置条件，例如等于、不等于、包含、为空、日期区间
- 配置排序，例如按时间、优先级、状态排序
- 配置分组，例如按状态、项目、标签分组
- 配置输出字段
- 保存为查询模板
- 生成可嵌入块或视图块

### 7.3 交互要求

- 提供可视化条件编辑器
- 对常用条件给出预设模板
- 当条件冲突或字段缺失时给予提示
- 提供“高级模式”显示生成后的查询表达

### 7.4 MVP 范围

- 单条件与多条件组合
- 基础排序
- 基础分组
- 字段选择
- 模板保存
- 嵌入生成

### 7.5 暂不支持

- 极复杂嵌套条件
- 高级聚合统计
- 自定义函数扩展
- 跨空间复杂联查

## 八、模块二：多视图结果面板 Multi View

### 8.1 功能目标

将同一份查询结果渲染为不同视图，并允许用户直接操作原始数据。

### 8.2 核心能力

- 表格视图
- 看板视图
- 日历视图
- 统计卡片视图
- 视图切换与保存
- 字段映射
- 点击结果跳转原始块
- 快速编辑常见属性，例如状态、日期、优先级

### 8.3 交互要求

- 不同视图之间切换流畅
- 保持同一查询结果的数据一致性
- 用户可以保存视图偏好
- 支持最少配置即可生成可用界面

### 8.4 MVP 范围

- 表格视图
- 看板视图
- 基础字段映射
- 快速属性编辑
- 保存默认视图

### 8.5 第二阶段可扩展

- 日历视图
- 时间线视图
- 图表统计
- 多人协作字段

## 九、关键用户流程

### 流程 1：创建任务视图

1. 用户打开查询构建器
2. 选择对象范围为任务块
3. 设置条件：状态不等于已完成，截止时间在未来 7 天内
4. 选择字段：标题、项目、负责人、截止日期、状态
5. 保存查询
6. 选择以表格或看板形式展示
7. 在视图中直接改状态或日期

### 流程 2：创建项目看板

1. 用户选择带有项目属性的块
2. 设置分组字段为状态
3. 保存查询模板
4. 切换到看板视图
5. 拖动卡片更新状态

## 十、数据与对象模型建议

### 核心对象

- QueryTemplate：保存查询配置
- ViewConfig：保存视图类型与字段映射
- ResultSet：当前查询结果集
- BlockRef：关联原始块

### 设计原则

- 查询与视图解耦
- 视图配置可复用
- 操作必须回写原始块数据
- 保持和思源块模型一致，不自行创造平行数据体系

## 十三、MVP 建议

建议第一版只做下面这些：

- 可视化查询条件配置
- 查询模板保存
- 表格视图
- 看板视图
- 基础字段映射
- 快速编辑状态和日期
- 生成嵌入块

只要这 7 项做好，就已经能覆盖任务、项目、阅读清单、会议记录四类高频场景。

## 十四、后续路线图

### Phase 1

- 查询构建器 MVP
- 表格 + 看板视图
- 模板保存

### Phase 2

- 日历视图
- 时间线视图
- 更多预设模板
- 属性 schema 建议

### Phase 3

- 任务中心深度集成
- 自动化规则联动
- 知识库仪表盘联动
- 引用网络分析联动

## 十五、结论

这个项目的核心价值，不是“再做一个查询功能”，而是把思源已经存在但难用的结构化能力，变成普通用户可以真正每天使用的工作界面。

一句话定义：

让思源从“能查询的块系统”，升级为“可视化、可交互、可复用的个人工作台”。
